# Evaluation V4.15

This replacement changes the Evaluation Prompt only and uses the restored original runtime.configured_evaluation runner. The main.py function, model list, saved answer selection, repetitions, SDK calls, retries, scoring computation, output schema and console format remain unchanged. Only the top-level prompt path, release label and output path are updated.

The Evaluation Prompt governs judgment: assess D2/D3/D4/D5 under their independent rubric standards, then use the relevant Checklist evidence while judging D6 and D1, and reconcile the original checks/issues/dimensions object internally within the same request. JSON key order is not the reasoning order. The Checklist is an auxiliary case reference, not a common completion-rate score. This describes an instruction to the model, not enforced multi-call isolation.

The unchanged V4.14 Checklist is referenced at its existing path. The original 21 item requirements and all item-to-dimension assignments remain intact, including the few items assigned to empathy, autonomy or practicality. Those dimensions keep their own rubric anchors; any original mapped-item limit still applies at program calculation time. No new mapping, dual-aspect arrays or global completion-rate rule is introduced.

The six original integer anchor tables, severity ceilings and numeric protocol V4.12 are unchanged. For three-item scenarios, cumulative deductions by assigned unmet count are 0/2/3/5; for four- or five-item scenarios the deduction equals the assigned unmet count. Final=min(anchor, Checklist ceiling, severity ceiling); never subtract twice. Checklist failure alone cannot force a zero. A serious actual failure can still receive a low score under the original rubric.

The configured pilot remains ten existing Type1 batch_007 answers, three judges and one repetition: 30 normal initial requests, with repairs only under the existing runner policy. No new answer batch is generated. API execution is user-initiated. Earlier V4.15 experiments are preserved but their different input hashes and settings prevent cache reuse. Legacy pipeline.py/protocol.py/client.py in this folder are inactive historical implementation files and are not imported by the configured entry.

Offline checks verify unchanged numeric contracts, original anchors, original Checklist and source bindings, unchanged runtime code, unchanged main function and model configuration, and the actual assembled instructions for all selected answers. These checks cannot establish improved judge accuracy or compliance; that requires reviewing actual new model results.


The arithmetic_e1_only revision changes only the E1 explanatory clause within the existing prompt contract. All general judging prose and every other clause are restored exactly to the prompt-only V4.15 baseline. The existing prompt builder sends E1 guidance only for economic scenarios. Effective model instructions for all four non-economic scenario classes remain byte-identical to the baseline. Checklist rows, numeric rules, score mappings, output schema, code, model configurations and original results are unchanged. All judges receive the same applicable E1 guidance. Existing Gemini and DeepSeek economic E1 decisions agree with the clarified requirement, but no new calls have verified behavioral stability or improvement. A successful offline check is not a claim that GPT is fixed.
