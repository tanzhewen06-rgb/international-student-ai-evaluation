# Evaluation V4.16

This working V4.16 release retains the approved E2 boundary and adds targeted wording for seven documented misjudgments: E1, E3, L1, L3, C1, C4 and A3. Unexposed or merely possible ambiguities are not changed. See Checklist_boundary_review.md for candidate and judge evidence, with scored records separated from unscored drafts. E2: An actual confusion between Monday-to-this-Friday (four days) and the student's mistaken ten days can fail E2. A correct four-day correction, equivalent planning for Friday, timeline wording, a verification question or conditionally planning for Friday must not by themselves be treated as a failed item or factual error. A real separate unsupported assertion can still be judged on its own merits under the existing rubric. Do not turn the student's mistake or the candidate's correction into a candidate defect.

Examples: "You have ten days, so next week is early enough" relies on the wrong window and fails E2. "That is four days, not ten; please confirm the deadline" does not fail E2. "Check the timeline and arrange payment by this Friday" does not fail merely for omitting an explicit day count. Quoting ten days only to correct it is not an error.

All other Checklist rows and prompt clauses remain unchanged. The existing substantive requirements are retained while the documented misreadings are explicitly excluded. Scenario bindings, six-dimensional anchors, item assignments, severity rules and score computation remain unchanged. The original cumulative deductions remain 0/2/3/5 for three-item scenarios and one point per assigned unmet item for four/five-item scenarios. Final=min(anchor, Checklist limit, severity limit), with no second subtraction.

The original runner, SDK adapters and console format remain in use. Root and Single entry points update only release/path settings; Single uses a release-setting variable instead of its former fixed label. Source answers, judge models, generation repetitions and the selected Single D6 case are unchanged. Older prompts, Checklists and results remain preserved. Actual model execution is user-initiated; installation and validation do not call models.

This release is prepared for the user to run. No new model calls establish that these wording clarifications fix behavior. Keep the initial data and any later corrective evaluations with their own input hashes and provenance; do not silently overwrite original judgments.
