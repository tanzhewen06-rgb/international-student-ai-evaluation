# Experiment Records

Edit `MODEL_NAME`, `BATCH_NAME`, `REPEAT_COUNT`, `PERSONA_FILE`, `STUDENT_BACKGROUND_FILE` and `SCENARIO_FILE` in Response Agent/main.py,
then run that file directly. With five scenarios, a repeat count of 1 makes five
generation requests. Every run has a new `run_id`; every attempt has a unique
`response_id`. Results are saved after each request, including failures.

## Compact JSONL storage (v2)

Each batch contains one `responses_<full_model_id>.jsonl` file per response model.
Each non-empty line is a complete JSON object, with no surrounding JSON array.

- The first line has `record_type="metadata"` and `schema_version=2`. Its `common`
  object stores the full persona once, its hash and provenance, model, batch,
  generation settings and logical record schema version. Its `scenarios` object
  stores each full scenario once, with its name and hash. `user_prompt_prefix`
  saves the exact prefix: `Scenario:\n` for old inputs, or a student-background
  block followed by that label when a profile is enabled. The four optional
  `student_background_*` fields in `common` save its filename, version, full
  prompt text and hash together; partial or inconsistent groups are rejected.
- All subsequent lines have `record_type="response"`. They contain `response_id`,
  `run_id`, UTC timestamp, `scenario_id`, repeat index, full `response_text`,
  success/error status, duration and error details. The model and batch are
  inherited from the header; they do not need repeating on every answer.

`record_format.py` is shared by both agents. It reconstructs each complete
logical record, including the exact original persona, scenario, user prompt,
model and settings. The user prompt is the saved prefix plus the saved scenario.
No prompt text is summarized, normalized or replaced with today's Markdown.

A file containing 25 attempts therefore has 26 JSONL objects: one metadata header
and 25 responses. The header is never counted as an answer or sent for scoring.
Opening the JSONL as 26 independent response records is incorrect.

## Repeated runs

Running the same model in the same batch appends response rows and keeps the
existing header. Before any model call, the writer checks the header against the
loaded persona, all scenarios, generation settings and provenance. A changed
prompt or setting requires a new batch. The program refuses to append compact
rows to an expanded legacy file, or to a file with an incomplete final line.
A per-file lock prevents two Response Agent runs from appending simultaneously.
Remove a stale `.jsonl.lock` only after confirming the previous run has stopped.

Prompt files are reloaded at the start of each execution. `main.py` contains the
run settings and model calls; `storage.py` manages saved records. No scores are
generated by the Response Agent. Scoring outputs are stored separately under
Evaluation Agent/evaluations, with independent evaluator/target run folders.

## Existing batch_001

The active `batch_001` contains losslessly converted compact files with the same
response filenames and 25 answers per model. All 50 complete logical records,
including every field, were checked against the legacy originals before the
duplicate legacy archive was removed. The Evaluation Agent input path remains valid.

The conversion does not call an AI or generate new answers or scores. Evaluation
Agent supports both legacy v1 files and the active compact v2 format.
Empty evaluation files and report templates are placeholders, not scoring results.

## Scope and failures

This format reduces repeated text in saved files. Generation still sends the
complete persona and scenario required for each request; file compaction alone
does not reduce API input tokens. API defaults remain defaults when the saved
generation settings object is empty. Server model versions, token usage and cost
are not reported by the current text-only model client. Keys are never stored.

Console output shows progress and the saved path; full answers and request error
details are in the file. Failed requests are saved without an automatic retry,
then the remaining scenarios continue. Disk-write failures stop the run. Any
failed request causes a nonzero exit code when the run finishes.

The current entry settings select `international_student_scenario_prompts V2.md` and `batch_003`, with Counselor V2 and Background V1. Saved scenario filename and version metadata follow the actual selected file; no separate version switch is needed.

Prompt Markdown files are stored in the Response Agent `prompts/` folder. The `SCENARIO_FILE` setting still takes a filename only.
